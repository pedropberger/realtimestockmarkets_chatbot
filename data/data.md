# Agent Logs Database Documentation

## Overview

The `agent_logs.db` file is a SQLite database that stores comprehensive logs of all AI agent interactions within the Stock Market AI Chatbot application. This database serves as a centralized repository for tracking model performance, monitoring usage metrics, and debugging agent behavior.

## Database Schema

### Table: `logs`

The main table storing all agent interaction logs with the following structure:

| Column | Type | Description |
|--------|------|-------------|
| `id` | INTEGER | Primary key, auto-incrementing unique identifier for each log entry |
| `timestamp` | TEXT | ISO 8601 formatted timestamp of when the interaction occurred (e.g., `2026-02-10T20:37:10.268503`) |
| `prompt` | TEXT | The complete input prompt sent to the AI model |
| `model` | TEXT | The AI model identifier used for the interaction (e.g., `gpt-5.2-chat`) |
| `tokens_input` | INTEGER | Number of tokens in the input prompt |
| `tokens_output` | INTEGER | Number of tokens in the model's response |
| `total_tokens` | INTEGER | Total tokens consumed (input + output) for billing and quota tracking |
| `latency_ms` | INTEGER | Response latency in milliseconds - time taken for the model to generate a response |
| `response` | TEXT | The complete response generated by the AI model |
| `tool_calls` | TEXT | JSON or text representation of any tool/function calls made by the agent (nullable) |

## Purpose and Use Cases

### 1. **Performance Monitoring**
- Track response latency trends over time
- Identify slow queries or performance bottlenecks
- Monitor model efficiency across different types of prompts

### 2. **Cost Analysis**
- Calculate token consumption and associated costs
- Analyze usage patterns by model type
- Forecast infrastructure expenses based on historical data

### 3. **Quality Assurance**
- Review agent responses for accuracy and relevance
- Debug unexpected or incorrect model behavior
- Conduct A/B testing between different models

### 4. **Audit Trail**
- Maintain a complete history of all agent interactions
- Support compliance and data governance requirements
- Enable conversation replay and investigation

### 5. **Analytics and Insights**
- Identify common user queries and patterns
- Measure average token consumption per interaction
- Analyze model selection patterns and effectiveness

## Example Queries

### Get the most recent logs
```sql
SELECT id, timestamp, model, total_tokens, latency_ms 
FROM logs 
ORDER BY timestamp DESC 
LIMIT 10;
```

### Calculate average latency by model
```sql
SELECT model, 
       AVG(latency_ms) as avg_latency,
       COUNT(*) as total_requests
FROM logs 
GROUP BY model;
```

### Total token consumption
```sql
SELECT SUM(total_tokens) as total_tokens_used,
       SUM(tokens_input) as total_input,
       SUM(tokens_output) as total_output
FROM logs;
```

### Find high-latency interactions
```sql
SELECT id, timestamp, model, latency_ms, total_tokens
FROM logs 
WHERE latency_ms > 5000
ORDER BY latency_ms DESC;
```

## Maintenance Recommendations

1. **Regular Backups**: Schedule periodic backups of the database to prevent data loss
2. **Data Retention**: Implement a retention policy to archive or delete old logs based on business requirements
3. **Indexing**: Consider adding indexes on `timestamp` and `model` columns for faster queries as the database grows
4. **Monitoring**: Set up alerts for unusual patterns (e.g., excessive latency, high error rates)

## Privacy and Security

- Ensure that sensitive information in prompts and responses is handled according to data protection policies
- Consider implementing redaction for PII (Personally Identifiable Information) before logging
- Restrict database access to authorized personnel only
- Encrypt the database file if storing sensitive financial or personal data
